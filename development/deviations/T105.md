# T105 — Venue page content sections ("What's happening here" / "nearby")

## Deviation 1 — Nearby section cannot filter past events (MV has no `starts_at`)

**What:** The ticket's nearby query specifies `ORDER BY ST_Distance ASC, starts_at ASC NULLS LAST`. The `discoverable_items` MV has no `starts_at` — gathering schedules live in `item_gatherings`. Without it, the nearby section shows past gatherings that are still published. The hosted section is unaffected (base-table query joins `item_gatherings` directly).

**Why:** Adding a column to the MV is a schema change outside this ticket's scope.

**Disposition:** flag-for-follow-up. Needs a ticket to add `starts_at` to the MV. The hosted section works correctly; the nearby section will show stale events until this lands.

## Non-deviations (spec/schema naming mismatches, no behavior impact)

- **Component name:** Ticket referenced `<ItemCard>`; no such component exists. Used `<ItemFeedCard>` (the locality feed's item renderer) — same thing the review intended.
- **`discoverability` column:** Ticket assumed `AND discoverability = 'public'`. No such column — the MV's own WHERE clause (published + not deleted + group listed/not dissolved) already restricts to public items. Same result.
- **Null card fields:** Hosted RPC returns null for `nearest_location_label` (redundant on the venue's own page), zero `response_count`, and null `primary_tag` — skips joins the card doesn't render. No visible difference.
