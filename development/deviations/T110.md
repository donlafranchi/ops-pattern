# T110 — RLS on event-log partitions + reserved embedding tables

## Deviation 1 — Migration applied via Supabase MCP, not `supabase db push`; ledger version needs repair

**What:** The other 33 migrations landed via `supabase db push`, which records the filename's
numeric prefix as the ledger version. This one was applied through the Supabase MCP
`apply_migration` tool, which recorded it as timestamp version `20260831185158` with name
`partition_rls` instead of `035`. The local file is `035_partition_rls.sql`, so the remote
ledger and the local filename disagree.

**Why:** `supabase db push` prompts for the database password interactively, which the agent
session cannot supply. The DDL applied is identical to the file's.

**Disposition:** flag-for-spec-revision — **Type A** (mechanical, no architectural decision).
**Resolved 2026-08-31** — PM ran `supabase migration repair`; the remote ledger now reads
`001`–`035` with `035 partition_rls` and no stray timestamp row. No further action.

## Deviation 2 — Created `member_events_y2026m11` as a verification artifact

**What:** Acceptance required proving that a *newly created* partition comes up with RLS enabled
— the whole point of patching the helpers. Verifying that meant calling
`ensure_member_events_partition('2026-11-01')`, which created the November partition ahead of
its normal rotation date.

**Why:** No other way to test the recurrence fix without waiting for a month boundary. The
partition is one `rotate_member_events_partitions()` call ahead of schedule and is exactly what
that function would have produced. It came up with `relrowsecurity = true`, confirming the fix.

**Disposition:** no action. The row count is zero and the partition is legitimate.

## Deviation 3 — `tests/ci-enforcement-rule-2.test.ts` was already patched under the prior commit

**What:** Not this ticket's change, but noted for the audit trail: the Rule 2 positive test
overwrote the whole exemptions ledger with its probe entry, assuming the real ledger was always
empty. It now merges instead. That fix shipped with the before-user-created hook (`deea5b6`).

**Disposition:** no action. Recorded so the two changes to CI-gate tests in one session are
traceable.
