# T097 — Locally Owned claim widget + server actions (F037)

## 2026-06-04 — Two minor deviations

1. **Add and Edit both call `setJurisdictionAction` (no separate update path).** The T075 handler folds update into `.set` as a soft-replace (T075 deviation #4), so the widget has no separate Edit action — Edit reuses the set wrapper. Matches the shipped handler; the scenario's "set/update/remove" framing maps to two handlers, not three.
2. **`ShopPublicPage` (a server component in `src/components/`) imports the server actions from `src/app/p/[...slug]/claim-actions.ts`.** A component→app-dir import crossing. Chosen so the actions co-locate with the route that owns the surface and the presentational component passes them to the client widget as props (idiomatic server-action-as-prop). Verified harmless to the jsdom unit tests (43/43 GREEN incl. the existing `ShopPublicPage.test.tsx`).

Owner-gating in the widget is UX/defense-in-depth; the security boundary is the handler's owner-role `AuthorizationError` + Zod ZIP validation (network-exposed server actions are safe against non-owner callers).

**Disposition:** no spec divergence requiring a SPEC-PATCH. M2 self-review PROCEED (no criticals).
