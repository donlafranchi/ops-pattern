# T137 — Findability follows what you've published

## Deviation 1 — "active Page membership" narrowed to an explicit managing role

**What:** The ticket's derivation reads "at least one active Page membership, or at least one published Item." The view (`038_member_has_published.sql`) counts only an *explicit* membership with the managing role for the Group's kind (owner/staff on business, steward elsewhere) in a Group whose `lifecycle_state = 'active'` — not any membership.

**Why:** `group_memberships.source` carries soft values (`soft_via_follow`, `soft_via_attendance`, `014_groups.sql:174`) and `role = 'member'` is what joining someone else's Group produces. Neither puts anything forward, and the rule exists to protect exactly that person. The role branch is the same one `member_has_standing_presence` already encodes; no user-visible difference today, because a plain member's own listings are covered by the published-Item branch.

**Disposition:** accepted-as-is.

## Deviation 2 — `member_prompts` dropped (the PM call the ticket deferred to build time)

**What:** Migration 038 drops the table, per the ticket's own recommendation.

**Why:** It existed for one prompt kind and that kind is gone; production carries zero rows. Applying the migration to production remains a deliberate human act (per T140's framing), so the PM can still veto before it runs.

**Disposition:** accepted-as-is.

## Deviation 3 — the spec still describes the prompt this ticket deleted

**What:** `product/systems/member.md` § Prompt-on-acquisition for producers / organizers (line ~275) and the "Helpful" bullet at line ~577 still describe the one-time prompt and the `member_prompts` substrate as the path by which producers become findable. `planning/stage-ledger/F060.md` line 38 names `acquisition-prompt.ts` as a live reader of the role rule.

**Why:** The ticket itself records both sections as "superseded in part by this ticket"; the PM's findability ruling replaced the prompt with a derivation. Spec text is product-owned, so the correction routes rather than lands here.

**Disposition:** flag-for-spec-revision

- **Applied:** resolver test fixtures now carry the id of the Member actually under test, so the projection row reads as real data rather than a placeholder.
