# T102 — `member_saved_searches` surface enablement

## Deviation 1 — DB-row assertions delegated to the F033 Playwright eval (not Vitest)

**What:** The ticket's Tests section asks for Vitest assertions that a row "exists in `member_saved_searches`" and "has `removed_at` set." The repo has **no live-DB Vitest infrastructure for handlers** (documented in `tests/actions-t075.test.ts` / `tests/actions-t091.test.ts`: "DB-touching behavior is verified by ... the Playwright eval against running Supabase"). The Vitest suites instead cover the wrapper logic that is testable without a DB — auth gate, default-label construction + 80-char truncation, `ActionError`→`Error` wrapping, and the exact handler call args (label + locationId / id) — by mocking `@/lib/supabase-server` and the two handlers. Real row insert / soft-remove / event emission is verified by the underlying T063 handler tests and will be exercised end-to-end by the F033 venue-page eval that consumes `<FollowVenueButton>`.

**Why:** Standing up live-Postgres Vitest infra for one substrate ticket would be over-engineering and would diverge from the established T091/T075 split. The mock-based tests fully lock the wrapper's own logic (everything T102 actually adds); the handler's DB behavior was already proven at T063.

**Disposition:** accepted-as-is. No SPEC-PATCHES entry — this is a test-layer convention, not a spec gap. F033 inherits the responsibility for the end-to-end row assertion when it builds the venue page.

## Deviation 2 — `@/actions` root barrel extended with two re-exports

**What:** `followVenueAction` imports `memberSavedSearchCreate` / `memberSavedSearchRemove` from `@/actions` (matching T092's `m/[handle]/actions.ts`, which imports `memberFollow` from the same root barrel). Those two handlers were exported from `@/actions/member` but not surfaced in the root barrel's convenience re-export block. Added the two lines.

**Why:** Consistency with the T092 wrapper pattern (import handlers from `@/actions`, not the sub-barrel). Two-line additive change; the registry and sub-barrel already exported them.

**Disposition:** accepted-as-is.
