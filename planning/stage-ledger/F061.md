That is the part expensive to retrofit and the reason this landed now. Three questions answered: the pin returns automatically via the same time window that drops finished gatherings; two appearances mean two pins and precedence *replaces* rather than adds, so the anchor never leaks back on the busiest day; the current resolution is shown to everyone, not only the owner. **+0.5 day, total 1.5–2 for the location piece.**
- **2026-09-07** · `reviewed` (third addendum, post-approval) — **a placement is a point or an area.** A Page with nothing scheduled is *of* an area, not *at* a place; the point returns only when there is an intention to meet. **Exposed a miss in binding note 9, written one hour earlier:** that note made the resolver return a *list* so "how many" could grow, but left the placement hard-coded to a point, so "what kind" was still a contract change. Second return-type change in one day; the note written to prevent the first did not prevent the second. **Free to fix — no code exists.** Verified against the map before pricing: the GeoJSON source is shared, but clustering is point-only, so areas need their own unclustered source plus fill and outline layers, and pins are DOM markers — two unrelated mechanisms, confirming this is new render work. **Split: the model stays in F061; the render leaves as [F062](../backlog/scenario-F062-the-map-shows-areas-as-well-as-pins.md).** **Addendum rather than re-approval** — the verdict does not change, and returning an approved scenario to the draft lane would make it unreadable to `build` in order to record a sharpening. **+0.5 day (model), total 2–2.5 for the location piece; render priced separately at 1–1.5.** The create flow gets *shorter* for area-shaped Pages — one question instead of two.
- **2026-09-07** · `reviewed` (fourth addendum, post-approval) — **appearances cannot overlap in time**; refused at creation, naming the conflict. **Binding note 9 checked for withdrawal and reaffirmed on narrower grounds:** one case still yields two placements — a Page with premises that also appears somewhere — so **an appearance replaces an *area* anchor and adds to an *address* anchor**, bounding the list at two rather than making it unnecessary. **This corrects "precedence replaces, it does not add"** from the second addendum, which was right for areas and wrong for addresses; the typing added in addendum 3 is what made the distinction expressible.
