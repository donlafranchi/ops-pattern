## Statements considered (and why not flagged)

### a. `ADR-0022:64` — Category 2 (refusal)

> "**Foreclosed:** MSA as an addressable URL tier. A future need for metro-level browsing is served by a `region`-kind row, not by reintroducing `msa`."

**Why not flagged.** Substantively covered by Intent annotation #1 ("the place tier must resolve *every* coordinate to exactly one anchor … MSAs leave ~1,200 rural counties unassigned"). The foreclosure follows one-step from the coverage rationale; a downstream agent reading the ADR has the tie-break rule (re-add MSA only if the coverage premise changes).

### b. `ADR-0022:20,50` — Category 3 (schema/UI naming split)

> "the UI naming layer can display 'Parish' / 'Borough' where appropriate … `county` schema value absorbs them uniformly via FIPS"

**Why not flagged.** The general schema-durable / UI-translates rule is established in `CLAUDE.md` § Naming conventions and applied here. Intent annotation #1 names FIPS coverage as the schema-side reason; the UI translation is a local application of the durable rule, not a new split needing its own Intent.

### c. `ADR-0022:22` — Category 5 (required-by-construction)

> "The suffix is applied always, not only on collision."

**Why not flagged.** The adjacent sentence carries substantive Intent inline: "makes the slug collision-proof by construction and non-enumerable." Tie-break rule for a downstream agent is clear (apply suffix unconditionally; don't optimize away on perceived-unique stems).

### d. `ADR-0022:22` — Category 1 candidate (suffix length)

> "`{title-derived-slug}-{short-random-suffix}` — e.g. `summer-concert-7gx9`"

**Why not flagged.** No numeric commitment is made in the ADR (4 chars appears only as an illustrative example). This is an *under-specification* to resolve at ticket time, not an un-annotated number. When the implementing ticket lands the constant, `pipeline-intent-check` should run against that ticket / the slug-generation system spec.
