# b1.x — Spec-Drain Sprint: SPEC-PATCHES queue clear before Phase 2

**Status:** Drafted 2026-05-27. Companion to [`b1.x-substrate-sprint.md`](b1.x-substrate-sprint.md) (which closed Phase 1's substrate work), [`../SPEC-PATCHES.md`](../SPEC-PATCHES.md) (the queue), and [`../STAGE-LEDGER.md`](../STAGE-LEDGER.md) (stamped on close).

## What this is

A small, contained work item — three spec patches landed in `product/`, one stale entry rescinded, a fourth patch opened to cover drift the original entries missed. **All Cowork-side.** No tickets, no migrations, no `web/` edits. The work lives in `explore`'s lane (the only skill the project trusts to write `product/`).

This sprint exists because three SPEC-PATCHES entries have been sitting in the open queue since 2026-05-19 and `rebuild-plan.md` Phase 2 cannot open until the queue is drained (per CLAUDE.md rule 13 + SPEC-PATCHES.md § Gate). Without a bundle file, the work would have lived as four loose file edits with no shared framing — exactly the pattern CLAUDE.md § Anti-sprawl is meant to prevent.

## Why this sprint, why now

Two pressures converged:

1. **Phase 2 gate.** SPEC-PATCHES has three open entries (-0001, -0002, -0003), all dated 2026-05-19. `explore` is the designated drain skill; the gate fires at every phase boundary. The longer the queue stays full, the more spec readers inherit the wrong text downstream.
2. **ADR-0021 supersede partially executed.** Ratification on 2026-05-23 retired `member_location_affinities` and three SECURITY DEFINER functions. A grep across `product/` (run 2026-05-27) found four sites still treat those retired identifiers as live. SPEC-PATCH-0003 — the original T049 flag — predates ADR-21 and targets text that no longer exists; rescinding -0003 alone would leave the actual drift uncatalogued. Hence SPEC-PATCH-0004 to capture the four real drift sites.
